# Nexus V3 技術規格（沙箱＋節點真的下載影片）— 草稿

> 2026-11-23｜狀態：**第 1 節 D1～D6 使用者已確認（全部照建議）**；進度：PR1 完成（`nexus/net/`：`sites.json`＋`sites.py`＋`guard.py`，電腦版 BRIDGE_HOSTS／BRIDGE_MEDIA_HOSTS 改讀它，打包 `--add-data`，selftest 檢查）。
> 依據：使用者規格書 §10（執行與沙箱）、§16.2～16.3、§24 V3；`02-架構決策.md` ADR-6、ADR-10；`01-差距分析.md` C2～C9；V2 驗收結果（`06` 第 12 節）。

## 0. 一句話

V3 讓 Master 可以派「**下載這部影片**」給節點，節點在**沙箱**裡用 yt-dlp＋ffmpeg 下載，檔案存在**節點那台電腦**。
檔案傳回 Master 是 V4 的事。

**沙箱的誠實說法**：這是「程序限制＋程式自己檢查」的**基本隔離**，擋得住「寫壞的程式或惡意網址讓任務吃光資源、寫到別的資料夾、亂連網站」；**擋不住**同一個 Windows 帳號下的惡意程式或電腦管理員。畫面和文件都會這樣寫，不會說成「完全隔離」。

## 1. 決策（2026-11-23 已確認）

| # | 問題 | 建議 | 理由 |
|---|---|---|---|
| D1 | 下載好的檔案放哪 | **留在節點那台**，節點小視窗可以選資料夾（預設 `下載\VideoHelper 節點`） | 傳回 Master 要驗證大小、雜湊、續傳，是 V4 的量；先把「安全地下載」做對 |
| D2 | 可以派哪些網站 | **只有電腦版已經能下載的網站**（現在的 `BRIDGE_HOSTS`＋`BRIDGE_MEDIA_HOSTS`：Pornhub、XVideos、XNXX、YouPorn、RedTube、xHamster、Tube8、YouJizz、SpankBang 共 9 個）；只擋廣告的網站一律不行 | 延續專案規則；這份清單抽成共用的 `sites.json`（安卓版 M2 也會用，一次做好） |
| D3 | 一台節點同時下載幾部 | **1 部**（節點小視窗可改成 2） | 同一台電腦測試時兩個節點各 1 部就夠；也避免把家用電腦拖慢 |
| D4 | 資源上限（預設） | 記憶體 **2 GB**、CPU **50%**、最多 **8 個子程序**、單部最長 **2 小時**、單檔最大 **8 GB**、開始前要有 **2 倍**預估大小的空間 | 一部 1080p 長片 ffmpeg 合併的實際需求再留餘裕；超過就停掉並說明原因 |
| D5 | 在哪裡建立下載任務 | **只在「📋 節點任務」**新增「下載影片（節點）」貼網址；① 下載影片 的本機下載完全不動 | 延續 V2「任務只在 Master 本機畫面建立」；不影響朋友平常的用法 |
| D6 | 沒辦法建立沙箱時 | **拒絕接任務**，畫面寫原因；**不會**偷偷不用沙箱照跑 | 規格 §10.2「不足就拒絕、不靜默降級」 |

## 2. 範圍

**做**：子程序執行器、Windows Job Object、每個任務自己的工作資料夾、環境變數白名單、網址／網路允許清單、路徑檢查、取消整個程序樹、結束後清理與孤兒程序檢查、沙箱能力偵測、`video.download` Adapter、共用 `sites.json`、GUI（新增下載任務、隔離等級、節點下載資料夾）、說明書、測試。

**不做**：檔案傳回 Master（V4）、Restricted Token／AppContainer／Windows Sandbox（列實驗）、OS 級防火牆規則（要管理員權限）、從 ① 下載影片 交給節點、非 Windows 節點（安卓走自己的 `vh_mobile.py`）。

## 3. 沙箱三層（ADR-6 具體化）

### 3.1 程序隔離
- `VideoHelper.exe --nexus-run <工作資料夾>`：節點用**同一個 EXE 的新模式**開子程序跑任務（打包後沒有獨立 python，所以用同一個 EXE）。yt-dlp 在這個子程序裡跑，**不在節點主程序內**。
- 子程序用 `CREATE_SUSPENDED` 開 → 放進 Job Object → 才恢復執行（避免還沒進 Job 就先生出子程序逃掉）。
- Job Object（ctypes，不加依賴）：記憶體上限、CPU 比例、子程序數上限、`KILL_ON_JOB_CLOSE`（節點當掉 → 整組自動結束）、`DIE_ON_UNHANDLED_EXCEPTION`；時間上限由節點計時。
- 取消／逾時：`TerminateJobObject` 一次結束整個程序樹（yt-dlp＋ffmpeg 全部），再列舉 Job 確認是 0 個程序才回報「已停止」。

### 3.2 檔案
- 每個任務一個隨機資料夾：`nexus\worker-<profile>\work\<隨機>\{input,output,tmp}`。
- 子程序只拿到白名單環境變數：`SYSTEMROOT`、`PATH`（只留系統＋程式自己的 ffmpeg）、`TEMP`／`TMP`→tmp、語系；**不傳** token、AI 金鑰、下載器設定、使用者 Cookie。
- 成功後把 output 裡的檔案搬到 D1 的資料夾：檔名重新清理、檢查真實路徑一定在目標資料夾內（擋 `..`、符號連結、保留字裝置名）、副檔名只允許 mp4／mkv／webm／m4a。
- 結束（成功、失敗、取消）都刪工作資料夾；刪不掉就回報「清理失敗」，**不假裝完成**（AT-024）。

### 3.3 網路
- 開始前：網址必須是 `https`、主機在 `sites.json` 的頁面網域內、埠 443。
- 下載過程：yt-dlp 的每個請求（含轉址、影片 CDN）都經過自訂檢查：主機要在 `sites.json` 的頁面或媒體網域內、轉址最多 5 次、**解析出的 IP 不能是私有網段／127.x／169.254.x（雲端 metadata）／IPv6 本機**（擋 DNS rebinding 打內網）。
- 這是程式自己擋，**不是 OS 防火牆**；文件照實寫。

### 3.4 能力偵測（每次節點啟動）
偵測：Job Object 能不能建、能不能設記憶體上限、Windows 版本、有沒有 ffmpeg、工作資料夾能不能寫、有沒有用管理員身分執行（有的話顯示警告）。
結果放進心跳的能力資料：`isolation: "basic"` 或 `"none"`＋原因。Master 排程時，`video.download` 只派給 `basic` 的節點；不合格的排除原因寫「沙箱不能用：…」。

## 4. `video.download` Adapter

```json
{ "type": "video.download", "adapter_version": "1.0",
  "params": { "url": "https://www.xvideos.com/video.abc123/...", "quality": "best|1080|720|480" },
  "limits": { "max_runtime_seconds": 7200, "max_output_bytes": 8589934592 } }
```
- Master 建立時就驗網址（不在 `sites.json` → 直接 REJECTED，畫面說原因）；節點收到再驗一次。
- 進度：每秒回報百分比、速度、剩餘時間（沿用 V2 事件）。
- 失敗分類沿用電腦版：等重試（429／斷線，交給 V2 的重試規則）、需要處理（影片被移除、網址錯，不重試）、空間不夠（不重試，提示清空間）。
- 結果：檔名、大小、SHA-256、存放路徑（只給 Master 看，不傳檔案）。Master 驗證欄位格式；真正收檔驗證是 V4。

## 5. 畫面

- **📋 節點任務**：「＋ 新增」多一個類型「下載影片（節點）」：貼網址、選畫質；詳情多「下載結果」（檔名、大小、存在哪台的哪裡）。
- **🖧 節點**名單：多一欄「隔離」（基本／不能用＋原因）。
- **節點小視窗**：「下載資料夾」選擇、「同時下載 1／2 部」、「隔離等級：基本（程序限制，不是完全隔離）」、目前下載的進度。

## 8. 風險

- **Job Object 在 PyInstaller 打包後的行為**（PyInstaller onefile 本身會先開一個子程序）：PR2 第一件事就是在 Windows CI 用打包後的 EXE 驗證，不行就改用 onedir 或調整建立方式，並先跟你說。
- **yt-dlp 請求檢查**：yt-dlp 內部有好幾種下載方式（HTTP、HLS 分段、ffmpeg 直接抓）。ffmpeg 直接連網的那種**沒辦法由程式逐一檢查**，V3 會關掉讓 ffmpeg 自己下載的模式（改成 yt-dlp 自己抓分段，ffmpeg 只做合併、不連網）；做不到的網站就不支援節點下載，並寫在清單裡。
- 真實網站測試只能在你的電腦或 GitHub Actions 做（開發環境連不到成人網站）。
