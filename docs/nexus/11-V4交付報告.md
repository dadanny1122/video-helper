# Nexus V4 交付報告：節點把影片傳回 Master

> 2026-11-24｜電腦版 v1.33.0、Nexus 0.4.0、協定 1.3｜規格：`10-V4傳回Master規格.md`（D1～D7 全部照建議）

## 1. 做了什麼（白話）

勾「下載完傳回這台」的任務，節點下載完會把影片切成每段 8 MB 傳回 Master。每段都比對 SHA-256，收齊後再比對整個檔案，對了才放進 ① 下載影片 的下載資料夾、寫進 ② 下載紀錄。斷線、節點重開、Master 重開都會從缺的那段接著傳。

## 2. 程式

| 位置 | 內容 |
|---|---|
| `nexus/master/incoming.py`（新） | 收檔：`uploads` 表的讀寫、段寫入（串流、每段 SHA-256、位元圖）、整檔驗證、搬進下載資料夾（清理檔名、副檔名白名單、`is_inside`、不覆蓋）、空間檢查、清理 |
| `nexus/storage/migrations.py` | migration 3：`uploads` 表 |
| `nexus/master/server.py` | 4 個端點（`POST /tasks/{id}/uploads`、`PUT /uploads/{id}/chunks/{n}`、`GET /uploads/{id}`、`POST /uploads/{id}/complete`）；只有 PUT 放寬到 8 MB；PUT 出錯一律斷線 |
| `nexus/tasks/dispatch.py` | `UPLOADING` 事件、`_finish_upload`、傳檔權限檢查、inbox「接著傳」提醒、24 小時逾時、半成品清查、`retry_return`；UPLOADING 離線不判 UNKNOWN |
| `nexus/tasks/states.py` | UPLOADING → CANCELLING；FAILED → UPLOADING（重新傳回）；`TRANSFER_FAILED`／`TRANSFER_EXPIRED` 不自動重試 |
| `nexus/tasks/scheduler.py` | 排除原因 `no_return`（協定 < 1.3）；UPLOADING 不佔節點名額 |
| `nexus/tasks/adapters.py` | `video.download` 多 `return_to_master`；新 `test.file`（測傳回用，不連網） |
| `nexus/worker/uploader.py`（新） | 節點上傳器：只傳缺的段、每段重試、等空間、斷線退避、照限速、只傳自己下載資料夾裡的檔 |
| `nexus/worker/executor.py` | 下載完 → UPLOADING → 上傳 → SUCCEEDED → 驗證成功才刪（可設定保留）；inbox `upload` 訊息接著傳；關閉中不再開新的傳回 |
| `nexus/gui/tasks_tab.py`、`nexus/worker/tray.py` | 「下載完傳回這台」、傳回進度、「↩ 重新傳回」、「測試檔」；節點小視窗「傳回後也留一份」、傳回狀態 |
| `video_helper_app.py` | 下載資料夾／限速接上 Master；收完寫 ② 下載紀錄（🖧）；瀏覽器「交給節點」預設傳回 |

## 4. 跟規格不一樣的地方

1. **一個檔案開一次傳檔**（`file_index`），不是一次送整個檔案清單：檔名／大小／雜湊只認 UPLOADING 時 Master 驗過的那份，之後的請求改不了，比較安全。
2. **瀏覽器腳本沒改**：「🖧 交給節點」由電腦版直接加上「傳回」，腳本不用升版。
3. **多一個 `test.file` 測試任務**：只有一台電腦也能測傳回、續傳，不用真的下載影片。
4. **傳回不佔下載名額**：傳回可能要等很久（例如等空間），不該擋住下一部下載。
5. 規格 §10 說「PR2 先在 Windows CI 量 2 GB 檔的速度和記憶體」：**沒做**。目前只用 1～8 MB 的檔案測過正確性，大檔速度要看你實機 T-08。
