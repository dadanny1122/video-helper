# Nexus V2 技術規格（任務管理與分散式排程）— 草案，待使用者確認

> 依據：使用者規格書 §11（狀態機）、§12（排程）、§13（重試）、§14（API）、§15（資料模型）、§24 V2、§25；
> V1 的決策與限制（`04-V1技術規格.md`、`05-V1交付報告.md`）。**標「待確認」的地方要使用者點頭才開工。**

## 0. 一句話

V2 讓 Master 可以「建立任務 → 挑一台合格的節點 → 派過去 → 節點回報進度 → 完成或取消」，而且每一步都有紀錄、說得出為什麼選這台。
**V2 只跑無副作用的測試任務**（回聲、等待、故意失敗），規格 §24 V2 明文要求先用測試工作負載；真的在節點上下載影片要等 V3 的沙箱，檔案傳回 Master 要等 V4。

## 1. 待確認的決策

| # | 決策 | 建議 | 理由 |
|---|---|---|---|
| D1 | V2 範圍只到測試任務 | 是 | 規格要求；沒有沙箱就讓節點跑下載＝讓 Master 能叫別台電腦連任意網站寫任意檔，違反 §10 |
| D2 | 任務只能在 Master 那台的 GUI 建立 | 是 | 延續 V1「管理操作不開網路端點」；規格 §14.2 的 `POST /tasks` 先不開 |
| D3 | 同一台電腦開兩個 Worker 做驗收 | 是，加 `--worker --profile 名稱` | 使用者目前只有一台家用電腦；兩個 profile＝兩個獨立身分、資料夾、日誌 |
| D4 | 任務畫面放在「⚙ 進階設定」新分頁「📋 節點任務」 | 是 | 不打擾平常只用下載的朋友；① 下載影片 的本機佇列完全不動 |

## 2. 範圍

**做**：Task Manifest＋schema 驗證、19 個狀態＋合法轉移表、建立／查詢／取消／idempotency、節點資源回報、硬性篩選＋可解釋評分、lease／ACK／事件序號、持久化（Master 重啟可恢復）、Task Center＋任務詳情＋排程理由、3 個測試 Adapter。

**不做**（留給後面版本）：沙箱與真實 Adapter（V3）、Artifact 上傳與驗證、UNKNOWN 自動核對（RECONCILING）、lease 過期後自動重跑執行中任務（V4）、RBAC（V5）。

## 3. 任務模型

### 3.1 Task Manifest（Master 產生、簽 SHA-256，Worker 收到時重算）

```json
{
  "manifest_version": 1,
  "task_id": "uuid",
  "type": "test.echo",
  "adapter_version": "1.0",
  "created_at": "2026-11-20T10:00:00Z",
  "expires_at": "2026-11-20T11:00:00Z",
  "idempotency_key": "使用者或 GUI 產生，最長 64 字",
  "params": { "text": "hello" },
  "limits": { "max_runtime_seconds": 60, "max_result_bytes": 4096 },
  "requirements": { "platform": "windows", "min_memory_mb": 0, "min_disk_mb": 0 },
  "retry_policy": { "max_attempts": 2 },
  "priority": 0
}
```

- 每個 Adapter 有自己的 `params` schema，**不認得的欄位一律拒絕**（AT-005）；整份 manifest 上限 16KB。
- `integrity`：Master 存 `manifest_sha256`（canonical JSON），派送時一起給；Worker 重算不符就拒收。

### 3.2 測試 Adapter（固定允許清單，不接受任何命令字串）

| type | params | 做什麼 | retry_safe | idempotent |
|---|---|---|---|---|
| `test.echo` | `text`（≤1000 字） | 回傳原文＋SHA-256 | 是 | 是 |
| `test.sleep` | `seconds`（1～600） | 等 N 秒、每秒回報進度；可取消（測取消、逾時） | 是 | 是 |
| `test.fail` | `code`（`ADAPTER_ERROR`／`RESOURCE_LIMIT`／`INVALID_INPUT`） | 固定失敗（測重試分類） | 是 | 是 |

- 在 Worker 程序內的執行緒跑，**不開子程序、不碰檔案、不連網**；結果是小 JSON（≤4KB）直接放在完成事件裡。
- 每個 Adapter 宣告 `retry_safe／idempotent／checkpoint_supported／side_effects="none"`（規格 §13.3）。

### 3.3 狀態機

19 個狀態全部定義（規格 §11.1），轉移表寫死在 `nexus/tasks/states.py`。V2 實際會走到的：

```
CREATED → VALIDATING → QUEUED → SCHEDULED → DISPATCHED → ACCEPTED → PREPARING → RUNNING → VERIFYING → SUCCEEDED
                └→ REJECTED          ↑            │(30 秒沒 ACK)                     │
                                     └────────────┘                                  ├→ FAILED →（可重試）新 attempt → QUEUED
                                                                                     ├→ TIMED_OUT → FAILED
                     任何非終態 ──取消──→ CANCELLING ──Worker 確認──→ CANCELLED      └→ CANCELLING
                     DISPATCHED 之後節點離線／被撤銷 → UNKNOWN（V2 停在這裡，GUI 可人工標記失敗）
```

硬性規則（規格 §11.2）：
- 狀態只能經 `TaskService.transition()` 改：檢查目前狀態、目標狀態、`version`（樂觀鎖）、操作者；**同一個交易**寫 task、attempt、audit。
- 終態不會回到 RUNNING；重試＝新的 `attempt`，舊的保留。
- Worker 事件用 `event_id`（去重）＋`(attempt_id, seq)`（順序）；重複的回 200 但不改狀態，倒退的拒絕（AT-012）。
- Master 重啟後從 SQLite 恢復，記憶體裡沒有唯一的佇列。

### 3.4 什麼情況重派、什麼情況不重派（誠實版）

| 情況 | V2 怎麼做 | 為什麼 |
|---|---|---|
| 派出去 30 秒內沒收到 ACK | 收回 → QUEUED，換一台；舊 lease 作廢，晚到的 ACK 被拒，Worker 收到拒絕就丟掉 | Worker 一定要等 Master 回「ACK 收到」才開始跑，所以沒 ACK＝確定沒開始（AT-009） |
| ACK 之後節點離線／被撤銷 | → UNKNOWN，**不自動重跑** | 不知道它有沒有跑完；V4 才做核對。測試任務沒副作用，但機制要先做對 |
| Adapter 回報失敗 | 照 retry_policy：`ADAPTER_ERROR` 可重試、`INVALID_INPUT`／`RESOURCE_LIMIT` 不重試 | 規格 §13.2 |
| 超過 `max_runtime_seconds` | Master 送取消；寬限 15 秒後 → TIMED_OUT → FAILED | Master 用自己的時鐘判斷 |
| 沒有合格節點 | 留在 QUEUED，詳情顯示每台被排除的原因（AT-016） | 不硬派 |

## 4. 節點資源回報與排程

### 4.1 心跳多帶的資料（協定 1.0 → 1.1，舊 Worker 照樣能心跳，只是不會被派任務）

`resources`：`cpu_count`、`cpu_load`（0～1，Windows 用 `GetSystemTimes` 算兩次差）、`memory_total_mb`、`memory_available_mb`（`GlobalMemoryStatusEx`）、`disk_free_mb`（Worker 資料夾）、`platform`、`arch`；
`adapters`：`{"test.echo": "1.0", …}`；`max_concurrency`（Worker 設定，預設 1）；`running`：目前任務 id 清單。
**不加新套件**（不用 psutil），全部標準庫＋ctypes。

### 4.2 硬性篩選（不過就排除，分數再高也沒用；規格 §12.1）

1. 裝置 ACTIVE、未暫停、有效憑證、心跳 ≤30 秒（CONNECTED）
2. 協定 ≥1.1、支援這個 Adapter 的同一主版本
3. 平台符合、`memory_available_mb`／`disk_free_mb` ≥ 任務需求
4. 執行中任務數 < `max_concurrency`

> 資源數字是 Worker 自己報的，**只拿來挑選，不拿來授權**（規格 25.3）。Worker 收到任務時自己再檢查一次，不夠就拒收。

### 4.3 評分（0～100，權重版本 `w1`，可在設定裡調）

| 子分數 | 計算 | 權重 |
|---|---|---|
| CPU_FIT | 1 − cpu_load | 0.25 |
| MEMORY_FIT | min(1, 可用 RAM ÷ 4096MB) | 0.25 |
| DISK_FIT | min(1, 可用磁碟 ÷ 10GB) | 0.10 |
| QUEUE_FIT | 1 − 執行中 ÷ max_concurrency | 0.25 |
| RELIABILITY | 最近 20 次（成功＋1）÷（總數＋2） | 0.15 |

GPU、網路 V2 不用 → 不列入（權重本來就沒給，不懲罰沒有 GPU 的節點）。
**同分**：執行中任務少的優先 → 再比 `device_id` 字典序（AT-017，結果可重現）。
每次排程存一筆 `schedule_decisions`：候選、每台子分數、排除原因、權重版本、最後選誰、時間。

## 5. 派送協定

Worker 主動連 Master（跟 V1 一樣，Master 不連 Worker）：

| 方法／路徑 | 誰 | 用途 |
|---|---|---|
| `GET /api/v1/workers/{id}/inbox?wait=25` | Worker（mTLS） | long-poll：有任務或取消指令就立刻回，沒有就 25 秒後回空 |
| `POST /api/v1/workers/{id}/task-ack` | Worker | `{task_id, attempt_id, lease_id, accept, reason}`；Master 回 `{ok, start: true/false}`，**`start: true` 才可以開始** |
| `POST /api/v1/tasks/{id}/events` | Worker | `{event_id, attempt_id, seq, type, data}`；type＝PREPARING／RUNNING／PROGRESS／SUCCEEDED／FAILED／CANCELLED |

- 都帶 V1 的訊息外框、nonce、速率限制；路徑上的 id 必須＝憑證裡的 id，task 必須真的派給這台（不然 `TASK_NOT_ASSIGNED`）。
- 未核准／暫停／撤銷的節點打 inbox → 跟心跳一樣被拒，**拿不到任何任務內容**（AT-001）。撤銷時 Master 把它所有 ACCEPTED 之後的任務改 UNKNOWN，Worker 收到撤銷就停止執行中的測試任務。
- 新錯誤碼：`TASK_NOT_FOUND`、`TASK_NOT_ASSIGNED`、`LEASE_EXPIRED`、`INVALID_TRANSITION`、`IDEMPOTENCY_CONFLICT`（同 key 不同內容）、`ADAPTER_UNSUPPORTED`（AT-018）、`MANIFEST_INVALID`、`EVENT_OUT_OF_ORDER`。

## 6. 資料模型（migration 0002，只新增表，不改 V1 的表）

| 表 | 主要欄位 |
|---|---|
| `tasks` | task_id、type、adapter_version、manifest_json、manifest_sha256、idempotency_key（UNIQUE）、status、version、priority、attempt_count、max_attempts、assigned_device_id、result_json、error_code、error_message、created_by、created_at、updated_at、expires_at |
| `task_attempts` | attempt_id、task_id、attempt_no、device_id、lease_id、lease_expires_at、status、accepted_at、started_at、ended_at、error_code |
| `task_events` | event_id（PK，去重）、task_id、attempt_id、device_id、seq、type、data_json、received_at；UNIQUE(attempt_id, seq) |
| `schedule_decisions` | decision_id、task_id、decided_at、weights_version、candidates_json、chosen_device_id |
| `device_capabilities` | device_id（PK）、resources_json、adapters_json、max_concurrency、observed_at |

狀態轉移的 audit 照樣寫進 V1 的 `audit_events`（不能改、不能刪）。

## 7. GUI：「⚙ 進階設定 → 📋 節點任務」

- 任務列表：名稱／類型、狀態（顏色）、節點、建立時間、嘗試次數；篩選「進行中／全部」
- 「＋ 新增測試任務」：選類型、填參數、（進階）需求與逾時；idempotency key 自動產生、可改（拿來測重複送出）
- 任務詳情：時間軸（每個狀態轉移和事件）、結果、**排程理由表**（每台節點的子分數、總分、為什麼被排除、最後選誰）
- 按鈕：取消（顯示「取消中…」直到節點確認）、UNKNOWN 時「人工標記失敗」（要理由，寫稽核）
- 只呼叫 `TaskService`，跟 V1 一樣不碰資料庫

## 8. Worker 端

- `--worker --profile 名稱`：資料夾 `nexus\worker-名稱\`，身分、設定、日誌全部獨立；不帶就是 `nexus\worker\`（V1 不變）
- Executor：最多 `max_concurrency` 個任務；收到任務先驗 manifest 雜湊、Adapter 版本、資源，不合就 `accept: false`＋原因
- 小視窗多一行「目前任務：…」；Worker 設定可關「接收任務」（關了 Master 就不會派）

## 10. 驗收測試

| 編號 | 情境 | 預期 |
|---|---|---|
| AT-001 | 未核准／暫停／撤銷的節點打 inbox | 拒絕、拿不到任務內容、audit |
| AT-004 | 同 idempotency key 送兩次 | 回傳同一個任務；同 key 不同內容 → `IDEMPOTENCY_CONFLICT` |
| AT-005 | 未知欄位、超大 manifest、參數超範圍 | 排程前就 REJECTED，不建立可執行任務 |
| AT-009 | 派送後 Worker 沒 ACK 就斷線 | 30 秒後回 QUEUED 換一台；晚到的 ACK 被拒、Worker 不執行 |
| AT-010（V2 版） | ACK 後 Worker 斷線／被撤銷 | UNKNOWN，不自動重跑、不宣稱成功 |
| AT-011（V2 版） | Master 在任務執行中重啟 | 任務、attempt、事件都在；Worker 重連後繼續回報，狀態接得上 |
| AT-012 | 同一事件送兩次、亂序 | 去重；狀態不倒退、不會完成兩次 |
| AT-015 | 取消執行中的 test.sleep | CANCELLING → Worker 停止並回報 → CANCELLED；在那之前 GUI 顯示「取消中」 |
| AT-016 | 沒有合格節點 | 留在 QUEUED，詳情列出每台的排除原因 |
| AT-017 | 兩台分數相同 | 固定選同一台（tie-breaker），重跑結果一樣 |
| AT-018 | Worker 不支援這個 Adapter 版本 | Worker 拒收＋`ADAPTER_UNSUPPORTED`，Master 換別台或留在 QUEUED |
| AT-020 | 既有下載回歸 | ci_smoke 全綠 |
| AT-023 | 大量 inbox／events | 速率限制生效、Master 不崩 |
| T-01 | 兩個 Worker（同一台電腦兩個 profile） | 各自接到不同任務並完成；排程理由看得到 |
| T-02 | 逾時 | test.sleep 600 秒、限制 5 秒 → TIMED_OUT → FAILED，節點真的停了 |
| T-03 | 重試 | test.fail ADAPTER_ERROR、max_attempts 2 → 兩個 attempt 都留紀錄、最後 FAILED；INVALID_INPUT 不重試 |
| T-04 | 舊版 Worker（協定 1.0） | 心跳正常、不會被派任務、排除原因寫「版本太舊」 |
| T-05 | manifest 被竄改 | Worker 重算雜湊不符 → 拒收 |

## 11. 明確不做（V2）

任何會碰檔案、網路、子程序的 Adapter；`video.download` 派送；Artifact 上傳；網路任務建立端點；自動核對 UNKNOWN；跨 attempt 的 checkpoint。
