# Nexus Phase 4：V1 實作計畫（Secure Device Connectivity）

> 2026-11-15 三項決策已確認。**PR 內容、API、資料模型、驗收測試以 [04-V1技術規格.md](04-V1技術規格.md) 為準**；本文件保留原始拆分與回復方式。

V1 目標（規格 §22）：Master 與 Worker 的安全通訊、註冊、核准、心跳、撤銷。**不開放任何遠端任務執行**。
原則：每個 PR 可獨立審查、可獨立回復；預設 `nexus.enabled = false`，既有使用者升級後什麼都不會變。

## V1 驗收腳本（兩台 Windows，手動）

1. A 電腦：開 VideoHelper → 進階設定 → 🖧 節點 → 開啟 Master，選網卡，記下指紋前 8 碼與配對碼。
2. B 電腦：`VideoHelper.exe --worker` → 輸入 A 的 IP：47331 與配對碼 → 畫面顯示「等待核准」與 A 的指紋前 8 碼（兩邊核對）。
3. A：Pending 出現 B（名稱、指紋、IP、版本）→ 核准（輸入原因）→ B 變 ACTIVE，最後心跳每 10 秒更新。
4. A：撤銷 B → B 立刻顯示「已被撤銷」；B 重啟 Worker → 仍被拒，不會自動恢復（AT-003）。
5. A：關掉 Master 再開 → B 狀態、憑證、稽核都還在（重啟後身分正確）。
6. A：安全分頁看稽核：register／approve／heartbeat 摘要／revoke 都有，沒有 token 或私鑰內容。
7. 既有功能：A、B 各下載一部影片成功（AT-020）。

## 不在 V1 的（避免偷跑）

任務建立／派送／執行、資源回報評分、沙箱、artifact 上傳、RBAC、憑證輪替、WAN。心跳 V1 只帶版本與狀態，**不帶** CPU／RAM（那是 V2 的 DeviceCapability，而且規格 25.3 禁止把未驗證的資源回報拿來授權）。

## 動工前要使用者決定的三件事（已於 2026-11-15 確認，見 04）

1. **誰是 Worker、在哪個網路**（ADR 末段）：同 LAN／VPN 可以；跨公網 V1 不支援。
2. **同意新增 `cryptography` 依賴**（ADR-4）；不同意就沒有 mTLS，只能退到「TLS 單向＋每裝置 HMAC」，仍然需要它來產 Master 憑證，所以其實沒得選，除非改用別的語言寫 Master。
3. **一個 EXE 兩種模式**（ADR-2）可以嗎？

三件都 OK 就從 PR1 開始。
