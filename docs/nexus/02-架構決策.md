# Nexus Phase 3：架構決策紀錄（ADR）

每一條：決定 → 為什麼 → 不選的替代方案 → 風險。對應規格 §24.1「必須由 Claude 在盤點後決定的項目」。
標 **[待使用者確認]** 的是會影響使用方式或依賴的決定，V1 動工前請拍板。

## ADR-1 模組邊界：新開 `nexus/` 套件，既有單檔不拆

- **決定**：所有 Nexus 程式放在新目錄 `nexus/`（見下方結構）。`video_helper_app.py` 只加三處：`import nexus`、「⚙ 進階設定」多一個「🖧 節點」分頁、`--worker` 命令列模式。既有 `TaskQueue`／`Bridge`／下載流程**一行不動**。
- **為什麼**：盤點 §5-1、§5-2：單檔已 5,200 行、狀態改動散在 15 處；塞進去會破壞既有下載（規格最高優先指令第 4 條）。
- **替代**：把整個 app 拆成多檔重構 → 規格 25.3 禁止「沒盤點就重寫」，而且風險全落在既有功能。
- **風險**：兩套任務模型並存（本機 `TaskQueue` vs Nexus Task）。V2 時用 Adapter 包住 `run_download()`，不合併模型。
- **結構**（依規格 6.2 縮減到第一版需要的）：

```
nexus/
  __init__.py          版本常數：NEXUS_VERSION、PROTOCOL_VERSION、MIN_PEER_PROTOCOL
  core/                models.py（dataclass）、enums.py、errors.py（錯誤碼）、config.py（schema_version＋migration）、masking.py
  storage/             db.py（SQLite 連線、WAL、migration）、migrations/0001_devices.sql …
  identity/            ca.py（私有 CA）、certs.py（簽發／驗證／指紋）、keystore.py（DPAPI 保護的 PEM 密碼）
  protocol/            messages.py（訊息外框 message_id/protocol_version/sent_at/sender_id/correlation_id）、schemas.py（手寫驗證，不用 pydantic）
  master/              server.py（HTTPS＋mTLS）、api_devices.py、ratelimit.py、audit.py、registry.py（裝置狀態機）
  worker/              agent.py（註冊、心跳、重連）、credstore.py、tray.py（無視窗模式）
  gui/                 devices_tab.py（進階設定的分頁；只顯示＋呼叫，不做安全決策）
  tests/               unit/、integration/、security/
docs/nexus/            本系列文件、threat-model.md、api-v1.md
```

## ADR-2 Master 與 Worker 同一個 EXE **[待使用者確認]**

- **決定**：還是只發布一個 `VideoHelper.exe`。平常開＝原本的下載器（可在設定裡開啟 Master）；`VideoHelper.exe --worker` ＝ Worker 模式（系統匣、無主視窗、第一次會跳出「輸入 Master 位址＋配對碼」小視窗）。
- **為什麼**：朋友本來就是下載同一個 EXE（盤點 §7）；一條打包、簽章、SBOM、attestation 流程；版本號一致，相容性檢查簡單。
- **替代**：分兩個 EXE → 兩倍打包時間、兩份 Release、使用者容易拿錯。
- **風險**：Worker 模式帶著整個 Tk／yt-dlp／ffmpeg（約 60MB）。可接受。

## ADR-3 控制通道：HTTPS REST（`/api/v1`）＋ Worker 主動連線，標準庫實作

- **決定**：`http.server.ThreadingHTTPServer` ＋ `ssl.SSLContext`，JSON 訊息，Worker → Master 單向發起。V1 只有註冊、核准狀態查詢、心跳、撤銷；V2 派送用「心跳回應夾帶待辦」＋ long-poll（`GET /api/v1/workers/{id}/inbox?wait=25`），不另開 WebSocket。
- **為什麼**：現有 Bridge 就是這套（盤點 §4），團隊（＝一個人）熟；零新依賴；防火牆只要 Master 開一個入站埠；規格 5.3 要求 Worker 主動連線。
- **替代**：WebSocket（要 `websockets`＋asyncio，跟 Tk 主迴圈混用麻煩）；gRPC（編譯 protobuf、體積大、對單人專案過重）。
- **風險**：long-poll 延遲最多幾秒 → 對下載任務無感。`ThreadingHTTPServer` 每請求一執行緒 → 用速率限制＋最大連線數（ADR-8）擋 DoS；SQLite 用每執行緒連線＋短交易。
- **埠**：預設 47331（跟 Bridge 的 47321～47325 區隔），綁定介面**由使用者在 GUI 選**（預設只列出私有網段 IP，不預設 0.0.0.0），並提示防火牆。

## ADR-4 身分：Master 當私有 CA，mTLS，新增 `cryptography` 依賴 **[待使用者確認]**

- **決定**：
  1. Master 第一次啟用時產生自己的 CA（ECDSA P-256）＋伺服器憑證。
  2. Worker 第一次連線：本機產生金鑰對＋CSR，連同裝置名、平台、版本、nonce 和**畫面上輸入的 6 位數配對碼**送 `POST /api/v1/devices/register`（配對碼只用來擋同網段亂送註冊的垃圾，**不等於核准**）。
  3. Master 建 PENDING 紀錄；使用者在「🖧 節點」分頁看到裝置名、指紋、來源 IP、版本後按「核准」（規格 8.1 第 33 條：明確的人類操作）。
  4. 核准 → 簽發 90 天裝置憑證（SAN 含 device_id、用途 clientAuth）。Worker 之後用它做 mTLS（`CERT_REQUIRED`），兩邊互相釘住對方指紋（Worker 釘 Master CA；Master 比對 DB 裡該裝置的憑證指紋）。
  5. 撤銷＝DB 標 REVOKED；握手後比對指紋不在有效名單就斷線（Python `ssl` 沒有方便的 CRL，用「短效期＋DB 指紋比對」達到等效）。輪替（V5）＝到期前 14 天 Worker 用舊憑證申請新憑證。
  6. 私鑰：PEM 用隨機密碼加密存檔，密碼用 DPAPI 保護（沿用 `protect_secret`）；`load_cert_chain(password=…)` 載入。私鑰不進日誌、不進診斷包。
- **為什麼要新依賴**：標準庫 `ssl` 能用憑證、不能簽憑證（盤點 §7）。`cryptography` 是 Python 事實標準、有 Windows wheel、`pip-audit`／SBOM 都吃得到。Windows 內建也沒有 openssl 可呼叫。
- **替代**：
  - 純 HMAC 每裝置密鑰＋Master 自簽憑證（不用新依賴）→ 仍要產生 Master 憑證，一樣需要 `cryptography`；而且少了 TLS 層的對端身分。
  - 用 Windows 憑證庫／CNG 走 ctypes → 工作量大、難測試。
- **風險**：`cryptography` 含原生程式庫，PyInstaller 打包要驗證（PR4 的 CI 就會驗）；EXE 大約 +4MB。
- **信任引導**：第一次核准時，Master 與 Worker 畫面都顯示對方指紋前 8 碼，說明書教使用者對一下（TOFU＋人工核對）。

## ADR-5 儲存：SQLite（標準庫），Nexus 設定獨立目錄

- **決定**：`%APPDATA%\VideoHelper\nexus\nexus.db`（WAL、外鍵開啟、`PRAGMA user_version` 做 migration）；`nexus\config.json`（含 `schema_version`）；憑證在 `nexus\pki\`；V4 的 artifact 在 `nexus\artifacts\<task_id>\`。既有 `settings.json`／`history.json` **不動**（規格 20）。
- **migration 規則**（AT-019）：升級前先複製 `nexus.db` → `nexus.db.bak-<舊版本>`；任一步失敗 → 回復備份、程式顯示錯誤與備份位置、Nexus 功能停用但下載器照常。
- **替代**：沿用 JSON 整檔覆寫 → 無交易、無唯一約束、多執行緒會互相蓋。
- **稽核表 append-only**：`audit_events` 建 trigger 禁止 UPDATE／DELETE；程式碼層也沒有對應函式。

## ADR-6 沙箱（V3 才實作，現在先定邊界與說法）

- **決定**：三層、誠實標示等級：
  1. **程序隔離**：任務一律在獨立子程序（yt-dlp 也改成子程序，不再在 Master／Worker 主程序內 `YoutubeDL`），掛 **Job Object**（記憶體上限、CPU rate、active process 上限、`KILL_ON_JOB_CLOSE`、wall-clock 由 Agent 計時），ctypes 呼叫，不加依賴。
  2. **檔案**：每任務唯一目錄 `nexus\work\<random>\{input,output,tmp}`，環境變數白名單（`TEMP`／`TMP` 指到 tmp），不傳任何 token；結束後清理並驗證無孤兒程序（枚舉 Job 內程序）。目錄 ACL 第一版用繼承預設，**不宣稱**能擋同一使用者帳號下的其他程式。
  3. **網路**：**Adapter 層允許清單**（scheme、host、port、redirect 次數、解析後 IP 不得是私有網段／localhost／metadata 位址、大小與逾時），由 `video.download` Adapter 在發請求前強制。**不是 OS 級網路隔離**（Windows 使用者態程式要擋任意子程序外連需管理員設防火牆規則；見差距分析 C5）。
- **Capability detection**：啟動時探測 Job Object 可用性、是否以管理員執行、Windows 版本、是否能建立 Restricted Token；結果存 DeviceCapability，GUI 顯示「隔離等級：程序限制（基本）」。任務若要求更高等級（manifest `isolation: "strong"`）→ 直接拒絕，不降級（規格 10.2）。
- **列為實驗／後續**：Restricted Token（`CreateRestrictedToken`，需處理 yt-dlp 讀使用者 Cookie 等相容性）、AppContainer、Windows Sandbox（需 Pro 版、啟動慢）。
- **威脅模型明說**：擋「寫壞的 Adapter／惡意輸入讓任務吃光資源、寫到任務目錄外、亂連網」；**不擋**「同一個 Windows 使用者下的惡意程式」或「本機管理員」（規格 2.2）。

## ADR-7 測試與 CI

- **決定**：加 `pytest`＋`ruff`（開發依賴，另開 `requirements-dev.in`，不進 EXE）。CI 三段：
  - `ubuntu`：ruff ＋ `nexus/tests/unit`（秒級，每次 push）。
  - `windows`：`nexus/tests/integration`＋`security`：真的起 Master（127.0.0.1、mTLS）、起 Worker 子程序，跑 AT-001／002／003／018／021／023（V1 範圍）。
  - 既有 `ci_smoke.py`／`net_test.py` 不動 ＝ AT-020 回歸。
- `build.yml` 的 `paths` 加 `nexus/**`、`requirements*.txt`；`net_test.py` 的 `ALLOWED` 不用加（Nexus 只連 LAN，不連外網）。

## ADR-8 日誌、稽核、速率限制

- 結構化 JSON 日誌 `nexus\nexus.log`（timestamp、level、component、event_id、correlation_id、device_id／task_id），`masking.py` 用正規表示式遮 `Authorization`、`token=`、`Cookie`、`-----BEGIN … PRIVATE KEY-----`，單元測試 AT-021。
- 速率限制：每來源 IP 的 token bucket（註冊 5 次/分、心跳 2 次/秒、其他 30 次/分）、最大同時連線 64、payload 64KB（V4 artifact 走另一條有配額的通道）。超限回 429＋`Retry-After`（跟既有 `retry_wait_seconds` 對得上）。

## ADR-9 平台與版本

- Windows 10 1809＋／Windows 11（DPAPI、Job Object、`DwmSetWindowAttribute(20)` 都有）。Python 3.12。
- 版本四件套：`VERSION`（App）、`NEXUS_VERSION`、`PROTOCOL_VERSION`（"1.0"，major 不同就拒絕）、Adapter 各自版本。心跳與註冊都帶齊，Master 拒絕時回 `PROTOCOL_INCOMPATIBLE`＋最低要求版本（AT-018）。

## ADR-10 Adapter 允許清單（V2 起）

- 第一版只有兩個：`video.download`（包住既有 `run_download()`，retry_safe=false、idempotent=依輸出檔是否已存在、checkpoint=分段續傳）、`test.echo`（睡 N 秒、寫一個檔，給 V2～V4 測試用，retry_safe=true）。
- **永遠不會有** `shell`／`python`／`powershell` 類 Adapter（規格 2.2、25.3）。

## 使用情境與範圍提醒 **[待使用者確認]**

規格 5.2：第一個可用形態是 **LAN Cluster**（同一個區域網路）。朋友的電腦如果不在同一個網路，V1 只能靠 VPN（例如 Tailscale／ZeroTier 把大家拉進同一個虛擬網段）才連得到 Master；公網 NAT 穿透是 Remote／WAN，規格明列非 MVP。請先想清楚：Worker 會是誰的電腦、在哪個網路？這決定 V1 做完有沒有人用得到。

## 工作量估計（誠實版）

| 版本 | 新增程式（含測試） | 說明 |
|---|---|---|
| V1 | 約 3,000～3,500 行、8 個 PR | 見 `03-V1實作計畫.md` |
| V2 | 約 3,000 行 | 狀態機、SQLite 任務表、排程、Task Center GUI |
| V3 | 約 2,000 行＋大量實機驗證 | Job Object／子程序化 yt-dlp 是最難驗的部分 |
| V4 | 約 2,500 行 | lease／reconcile／artifact 上傳＋驗證 |
| V5 | 約 2,000 行＋文件 | RBAC、輪替、簽章 manifest、稽核匯出 |

每個版本都比目前整個 Nexus 以前的任何一次改版大。建議一次只做一個版本，做完真的在兩台電腦上用過再往下。
