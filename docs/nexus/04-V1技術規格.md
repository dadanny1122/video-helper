# Nexus V1 技術規格（依 2026-11-15 三項決策與額外要求更新）

本文件是 V1 動工的依據，取代 `02-架構決策.md` 中與之衝突的敘述。範圍不變：**兩台 Windows 安全連線、核准、心跳、撤銷**；不派任務、不遠端下載、不執行任何命令。

## 1. 使用者決策（原文摘要）與落實方式

| 決策 | 落實 |
|---|---|
| V1 只支援 LAN；預留 VPN（Tailscale）；不暴露公網；LAN 不是信任邊界；位址／埠可設定 | §2 網路 |
| 加入 `cryptography`；`ssl` 做 TLS／mTLS；完整憑證生命週期（簽發、驗證、更新、過期、撤銷）；鎖版＋SBOM | §4 身分與憑證 |
| 單一 EXE 雙模式；兩模式獨立設定／日誌／生命週期；下載器不自動啟 Worker；Worker 明確啟動；最小權限 | §3 雙模式 |
| 額外 1～5：獨立身分、撤銷使既有連線失效、舊憑證不得復活、Master 重啟／Worker 斷線／憑證失效有明確處理、全部留稽核 | §5 安全處理機制、§7 稽核 |

## 2. 網路

- **綁定位址可設定**（`master.bind_host`、`master.port`，預設埠 47331）。GUI 下拉只列本機網卡位址，並標示類別：
  - 私有網段 `10/8`、`172.16/12`、`192.168/16` → 「區域網路」
  - `100.64/10`（CGNAT，Tailscale 用）→ 「VPN（Tailscale）」，V1 允許選，介面文字寫「跨網路連線請用 VPN」
  - `127.0.0.1` → 「只有本機（測試）」
  - `0.0.0.0`／公網位址 → **預設不列出**；設定檔手動填 `0.0.0.0` 時啟動要再按一次「我知道風險」並寫 audit（`master.bind_all_confirmed`）。
- 不做 UPnP／NAT-PMP、不做任何自動 port forwarding。
- Worker 端 `worker.master_url`（`https://主機:埠`）可設定；主機可以是 IP 或 Tailscale 名稱。
- **LAN 不是信任邊界**：同網段任何連線都只能走 `/register`（要配對碼）或帶有效裝置憑證的 mTLS；沒有任何「同網段免驗證」路徑。
- 所有連線：connect timeout 5s、read timeout 30s、單一請求 payload ≤ 64KB、每 IP 速率限制（§6）。

## 3. 雙模式（`VideoHelper.exe` vs `VideoHelper.exe --worker`）

| | 下載器模式 | Worker 模式 |
|---|---|---|
| 進入點 | `App(root)`（不變） | `nexus.worker.tray.main()`；**不建立 `App`**、不載入 `Bridge`、不讀 `settings.json`／`history.json`／AI 金鑰 |
| 設定 | `%APPDATA%\VideoHelper\settings.json`（不變）＋ Master 設定 `nexus\master\config.json` | `nexus\worker\config.json` |
| 資料 | `nexus\master\nexus.db`、`nexus\master\pki\` | `nexus\worker\identity\`（私鑰、憑證、釘選的 Master CA 指紋）、`nexus\worker\state.json` |
| 日誌 | `video_helper.log`（不變）＋ `nexus\master\master.log` | `nexus\worker\worker.log` |
| 啟動 | Master 由使用者在「🖧 節點」分頁按「啟用」（`master.enabled`，預設 false）；程式啟動時若 enabled=true 才隨之啟動 | 只在帶 `--worker` 時啟動；下載器模式**沒有任何路徑**會啟動 Worker |
| 生命週期 | 跟主視窗 | 系統匣常駐；「結束」= 送 `/disconnect` → 關閉 |
| 最小權限 | — | Worker 程序不持有 Bridge token、AI 金鑰、下載器設定；只讀寫 `nexus\worker\`；V1 沒有任務所以不碰 Downloads。**限制**：同一個 Windows 使用者帳號下無法再降 OS 權限（需要管理員建立受限 token），V3 再評估 |

兩模式**不能同時以同一身分存在**：同一台電腦要同時當 Master 和 Worker（單機測試）時，Worker 是獨立的 device_id 與憑證，走一模一樣的註冊核准流程（規格 5.2 Local Single Node）。

## 4. 身分與憑證生命週期

### 4.1 元件
- **Master CA**：ECDSA P-256，自簽，有效 10 年，`pki\ca.crt`＋`pki\ca.key`（加密 PEM；密碼 32 bytes 隨機，DPAPI 保護存 `pki\ca.key.dpapi`）。
- **Master 伺服器憑證**：由 CA 簽，1 年，SAN 含所有綁定 IP＋`master.hostname`；到期前 30 天自動換發（重啟時檢查）。
- **裝置憑證**：由 CA 簽，**90 天**，CN=`device_id`（UUID4），SAN URI `urn:vh:device:<device_id>`，EKU clientAuth，序號隨機 128-bit。
- **Worker 金鑰**：ECDSA P-256，本機產生，私鑰加密 PEM＋DPAPI 密碼；**每次重新註冊都換新金鑰**。

### 4.2 流程
1. **簽發（註冊）**：Worker 產生金鑰＋CSR → `POST /register`（配對碼、nonce、裝置資訊、CSR）→ Master 驗配對碼（6 位、5 分鐘、一碼一次、猜錯 5 次作廢）、CSR 公鑰演算法、nonce 未用過 → 建 `devices` PENDING＋回 `registration_token`（只給這次輪詢用）。
2. **核准**：使用者在 GUI 看裝置名／公鑰指紋／來源 IP／版本 → 核准（二次確認＋原因）→ Master 簽裝置憑證 → `credentials` 一筆（ACTIVE）→ 裝置 ACTIVE。Worker 用 `registration_token` 輪詢 `GET /registration`，拿到憑證＋CA 憑證**一次**（之後該 token 作廢），釘選 CA 指紋。
3. **驗證（每次連線＋每個請求）**：TLS 握手 `CERT_REQUIRED`＋我們的 CA；握手後取對端憑證指紋 → 查 `credentials`：必須 status=ACTIVE、未過期、`device.status=ACTIVE`；任一不符 → 回 `DEVICE_NOT_ACTIVE`／`CREDENTIAL_REVOKED`／`CREDENTIAL_EXPIRED` 並**關閉連線**。不只在握手查，每個請求都查（撤銷才會立即生效）。
4. **更新（renew）**：到期前 14 天，Worker 用現有憑證（mTLS）送新 CSR → `POST /renew` → Master 簽新憑證、舊憑證標 `SUPERSEDED`（給 24 小時重疊期讓 Worker 切換，之後拒絕）。更新不需要人工核准（裝置仍是同一身分）；更新失敗 → Worker 顯示警告，到期後進入第 5 點。
5. **過期**：握手或請求查到過期 → 拒絕；Worker 畫面「憑證已過期，請重新配對」；重新配對 = 新金鑰、新 PENDING、需要人工再核准；舊 device_id 標 `EXPIRED`，不復用。
6. **撤銷**：GUI 撤銷（二次確認＋原因）→ 同一交易：`devices.status=REVOKED`、該裝置所有 `credentials.status=REVOKED`、寫 audit → 立刻**關閉該裝置所有活連線**（§5-2）→ 之後任何請求／握手都被拒。**REVOKED 的 device_id 永久不可回到 ACTIVE**；同一台電腦要再加入只能重新註冊成新 device_id、新金鑰、重新核准。`revoked_fingerprints` 表永久保留指紋，即使 DB 裡裝置被清理也擋得住舊憑證。

### 4.3 金鑰保護
- 私鑰永不以明文落地；日誌遮罩 `-----BEGIN`；診斷包排除 `pki\`／`identity\`。
- CA 私鑰只在簽發時解密到記憶體。
- 非 Windows（CI 的 Linux 單元測試）：DPAPI 不可用時用檔案權限 0600 並在日誌警告「金鑰保護等級：檔案權限」；Windows 正式版一律 DPAPI。

## 5. 安全處理機制（額外要求 2～4）

| 情境 | Master | Worker |
|---|---|---|
| **撤銷** | 同交易改狀態＋audit；`ConnectionRegistry` 找到該 device_id 的 socket 全部 `shutdown`；之後請求層每次查 DB 擋掉 | 下一次請求收到 `CREDENTIAL_REVOKED` → 刪除本機憑證（保留加密私鑰供鑑識但標記作廢）、狀態「已撤銷，需重新配對」、停止心跳、不自動重試 |
| **Master 重啟** | 全部狀態從 SQLite 載入；啟動自檢：DB `user_version`、CA／伺服器憑證可載入且未過期、綁定位址仍存在、`pki\` 權限；任一失敗 → Master 不啟動、GUI 顯示原因（fail closed）。所有裝置 `connection_state` 設為 UNKNOWN，等心跳恢復 | 連線失敗 → 指數退避重連（5s→…→5min，用既有 `retry_wait_seconds` 風格）；重連時重新驗 Master CA 指紋（不符＝可能被換掉 → 停止並警告，不自動信任新 CA） |
| **Worker 斷線** | 心跳間隔 10s；逾 3 次（30s）→ `connection_state=STALE`、GUI 顯示「失聯 Xs」；逾 5 分鐘 → `OFFLINE`（V1 只影響顯示與 audit，因為沒有任務） | 退避重連；重連成功後補送一筆 `reconnected` 事件 |
| **憑證失效** | 握手／請求層拒絕＋audit `credential_rejected`（原因：expired／revoked／unknown） | 見 §4.2 第 5 點 |
| **Worker 正常結束** | 收到 `/disconnect` → `connection_state=DISCONNECTED`＋audit | 系統匣「結束」送 disconnect 後關閉 |

連線追蹤：Master 在 TLS 握手成功後把 `(device_id, socket, since)` 放進 `ConnectionRegistry`（記憶體）；撤銷／暫停時依 device_id 關閉。HTTP keep-alive 連線最多 60 秒閒置，確保就算 registry 漏掉也很快自然斷。

## 6. API（`/api/v1`，JSON；所有回應帶訊息外框）

訊息外框（請求與回應都有）：`protocol_version`、`message_id`（UUID）、`sent_at`（UTC ISO-8601）、`sender_id`、`correlation_id`、`nonce`（請求）。Master 保存 `(sender_id, nonce)` 10 分鐘拒絕重放；`sent_at` 與伺服器時間差 > 5 分鐘拒絕。

| 方法 路徑 | 身分 | 用途 | 速率限制（每來源 IP） |
|---|---|---|---|
| `POST /devices/register` | 無憑證＋配對碼 | 提出註冊（CSR） | 5/分 |
| `GET /devices/{id}/registration` | 無憑證＋`registration_token` | 輪詢核准狀態；核准後一次性取得憑證 | 12/分 |
| `POST /devices/{id}/heartbeat` | mTLS，且 id 必須等於憑證裡的 device_id | 心跳（sequence、agent_version、protocol_version、status） | 2/秒 |
| `POST /devices/{id}/renew` | mTLS | 憑證更新（CSR） | 2/分 |
| `POST /devices/{id}/disconnect` | mTLS | 正常下線 | 6/分 |
| `GET /system/info` | mTLS | Master 版本、協定版本、最低 Worker 版本 | 30/分 |

**核准／拒絕／暫停／恢復／撤銷／列表在 V1 只有本機 GUI 能做**（同程序呼叫 `registry`），不開網路端點：少一整類遠端管理攻擊面；規格 14.2 的 Admin 端點留到有 RBAC 的 V5 再開。

錯誤格式照規格 14.3。V1 錯誤碼：`PAIR_CODE_INVALID`、`PAIR_CODE_EXPIRED`、`PAIR_CODE_BURNED`、`REGISTRATION_NOT_FOUND`、`DEVICE_PENDING`、`DEVICE_NOT_ACTIVE`、`DEVICE_SUSPENDED`、`CREDENTIAL_REVOKED`、`CREDENTIAL_EXPIRED`、`CREDENTIAL_MISMATCH`（憑證 device_id ≠ 路徑 id）、`PROTOCOL_INCOMPATIBLE`、`AGENT_VERSION_TOO_OLD`、`REPLAY_DETECTED`、`CLOCK_SKEW`、`RATE_LIMITED`（含 `Retry-After`）、`PAYLOAD_TOO_LARGE`、`SCHEMA_INVALID`、`INTERNAL_ERROR`（不帶細節）。

## 7. 資料模型（SQLite，`nexus\master\nexus.db`，migration 0001）

```
devices            device_id PK, name, platform, agent_version, protocol_version, status(PENDING|ACTIVE|SUSPENDED|REVOKED|EXPIRED|REJECTED),
                   public_key_fingerprint, source_ip_first, created_at, approved_at, approved_reason, revoked_at, revoked_reason,
                   last_seen_at, connection_state(UNKNOWN|CONNECTED|STALE|OFFLINE|DISCONNECTED), last_sequence, version(樂觀鎖)
credentials        credential_id PK, device_id FK, serial_hex UNIQUE, fingerprint_sha256 UNIQUE, issued_at, expires_at,
                   status(ACTIVE|SUPERSEDED|REVOKED|EXPIRED), superseded_by, revoked_at
revoked_fingerprints fingerprint_sha256 PK, device_id, revoked_at, reason        -- 永久保留，即使裝置列被清
registrations      device_id PK, registration_token_hash, pair_code_hash, csr_pem, expires_at, delivered_at
nonces             sender_id, nonce, seen_at  (PK sender_id,nonce；10 分鐘清理)
audit_events       audit_id PK, ts, actor(owner|worker:<id>|system), action, resource_type, resource_id, outcome, reason,
                   correlation_id, details_json(已遮罩)   -- trigger 禁止 UPDATE/DELETE
schema_meta        key, value  (schema_version、created_at、last_migration_at)
```

必記 audit action（額外要求 5）：`device.register_requested`、`device.register_rejected`（含速率／配對碼錯誤）、`device.approved`、`device.rejected`、`device.suspended`、`device.resumed`、`device.revoked`、`credential.issued`、`credential.renewed`、`credential.rejected`、`device.connected`、`device.heartbeat_stale`、`device.offline`、`device.disconnected`、`master.started`、`master.stopped`、`master.selfcheck_failed`、`config.bind_all_confirmed`。心跳本身不逐筆寫 audit（只更新 `last_seen_at`），避免灌爆。

Worker 端 `state.json`：`device_id`、`master_url`、`master_ca_fingerprint`、`credential_expires_at`、`last_status`、`schema_version`。

## 10. 明確不做（V1）

任務／派送／執行／Adapter、資源回報（CPU／RAM）、排程、artifact、RBAC（只有 Owner＝本機 GUI 與 Worker 兩種角色）、遠端管理端點、WAN／NAT 穿透、UPnP、自動更新。
