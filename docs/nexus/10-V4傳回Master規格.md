# Nexus V4 規格：節點把下載好的影片傳回 Master — 草稿

> 2026-11-24｜狀態：**草稿，等使用者確認第 1 節 D1～D7**，確認後才寫程式。
> 依據：使用者規格書 §24 V4（結果回傳）；`07-V3技術規格.md` D1（V3 檔案先留在節點）；V3／V3.1 實機驗收（`08-V3交付報告.md`）。

## 0. 一句話

節點下載完影片後，**自己把檔案分成一段一段傳回 Master**；斷線可以接著傳，Master 收完**比對大小和 SHA-256**，對了才放進下載資料夾、任務才算「成功」。

白話說明：現在節點下載的影片留在節點那台電腦。V4 之後，你在家用電腦（Master）派工，影片最後會出現在**家用電腦**的下載資料夾，不用自己去節點那台拿。
（你目前只有一台電腦，同機 profile a／b 也能測；真正派上用場是有第二台電腦當節點的時候。）

## 1. 決策（請確認）

| # | 問題 | 建議 | 理由 |
|---|---|---|---|
| D1 | 誰連誰 | **節點主動上傳給 Master**（走現在的 mTLS 連線） | 節點本來就不開任何埠；不用多開防火牆、不多一個攻擊面 |
| D2 | 每個任務都要傳回嗎 | 新增任務多一個勾選「**下載完傳回這台**」，**預設勾**；瀏覽器「🖧 交給節點」也預設傳回 | 有時候只想放在節點那台（例如節點硬碟比較大），留一個選擇 |
| D3 | 傳完後節點那份 | Master **驗證成功後才刪**節點那份；節點小視窗可改成「保留」 | 節點通常是借來的電腦，不要堆檔案；但沒驗證成功絕不刪 |
| D4 | Master 收到放哪 | 跟 ① 下載影片 **同一個下載資料夾**，並且出現在 **② 下載紀錄**（標「來自節點 xxx」） | 平常找影片、做 AI 字幕都在 ② 下載紀錄，不用多學一個地方 |
| D5 | 一段多大、要不要限速 | 一段 **8 MB**、每段自己的 SHA-256；**不限速**，但沿用 ③ 設定 的「下載限速」當上傳上限（有設才限） | 8 MB 斷線最多重傳 8 MB；家裡網路內傳檔通常不用限速 |
| D6 | Master 空間不夠 | **先不傳**，任務停在「傳回中（等空間）」，畫面提示清空間，每 5 分鐘再試；檔案留在節點 | 不能因為 Master 滿了就把節點那份弄丟 |
| D7 | 傳不回來多久放棄 | 節點離線或一直失敗 **24 小時**後任務改「失敗：傳回逾時」，**檔案留在節點**，詳情寫在哪台哪裡；可按「重新傳回」 | 節點關機過夜很常見；24 小時夠回來接著傳 |

## 2. 範圍

**做**：分段上傳＋續傳、每段與整檔 SHA-256、大小檢查、Master 收檔路徑檢查、任務狀態走 `RUNNING → UPLOADING → VERIFYING → SUCCEEDED`、取消／逾時清掉半成品、Master 重開後接著收、② 下載紀錄整合、「重新傳回」、GUI 進度、說明書、測試。

**不做**：Master 傳檔**給**節點（沒需求）、節點之間互傳、壓縮（影片本來就壓過）、斷點以外的加速（多條連線同時傳）、雲端中轉。

## 3. 流程

```
節點下載完（沙箱，同 V3）
  → 送事件 UPLOADING（附檔名、大小、SHA-256）
  → POST /tasks/{id}/uploads          開一個傳檔工作，Master 回 upload_id、哪幾段已經有了
  → PUT  /uploads/{uid}/chunks/{n}    一段一段傳（已經有的跳過）
  → POST /uploads/{uid}/complete      Master 算整檔 SHA-256，對了 → 搬進下載資料夾
  → 任務 VERIFYING → SUCCEEDED；節點收到「已收到」才刪自己那份（D3）
```

斷線、節點重開、Master 重開：節點重新 `POST /tasks/{id}/uploads`，拿到「已經有的段」，從缺的開始傳。

## 4. API（協定 1.3）

| 端點 | 內容 | 限制 |
|---|---|---|
| `POST /tasks/{task_id}/uploads` | JSON：`files:[{name,size,sha256}]` → `upload_id`、`chunk_size`、`have:[段號…]` | 只有被派到這個任務的節點；任務要在 RUNNING／UPLOADING；30/分 |
| `PUT /uploads/{uid}/chunks/{n}` | **內容是檔案本身（不是 JSON）**；外框放 `X-VH-Envelope`（含 nonce）、`X-VH-Chunk-SHA256` | 一段 ≤ 8 MB（這個端點才放寬，其他端點還是 64 KB）；段號、長度要跟宣告的大小對得上；600/分 |
| `GET /uploads/{uid}` | 目前收到哪幾段 | 60/分 |
| `POST /uploads/{uid}/complete` | Master 驗整檔 → 回 `ok` 或錯誤碼 | 30/分 |

新錯誤碼：`UPLOAD_NOT_ALLOWED`（不是你的任務）、`CHUNK_MISMATCH`（這段雜湊不對，重傳這段）、`SIZE_MISMATCH`、`HASH_MISMATCH`（整檔不對 → 全部重傳一次，再錯就失敗）、`MASTER_DISK_FULL`（D6）、`UPLOAD_EXPIRED`（D7）。

## 5. 安全（收檔這一端一律不相信節點）

- 檔名**Master 自己再清理一次**（沿用 `sanitize_filename`），副檔名只收 mp4／mkv／webm／m4a；最終路徑用 `is_inside` 確認在下載資料夾內、不覆蓋（`unique_target`）。
- 大小：宣告大小 ≤ 任務的 `max_output_bytes`（預設 8 GB），每段長度、總長度都要對得上；多送的直接拒絕。
- 半成品放 `%APPDATA%\VideoHelper\nexus\incoming\<upload_id>\`，**驗證成功前不會出現在下載資料夾**。
- 每段請求都有 nonce＋時間檢查（同 V1 防重放）；upload_id 綁定「裝置＋任務」，被撤銷的節點立刻不能傳。
- 取消任務、任務失敗、超過 24 小時沒動的半成品 → 刪掉；刪不掉照實回報（同 AT-024）。
- 稽核紀錄：開始傳、完成、驗證失敗、被拒絕都記（只記檔名和大小，不記內容）。
- 誠實標示：SHA-256 保證「收到的跟節點送的一模一樣」，**不保證影片本身安全**；影片來源一樣只限 `sites.json` 的網站。

## 6. 狀態與資料

- 資料庫 migration 3：`uploads` 表（upload_id、task_id、device_id、檔名、大小、sha256、已收段的位元圖、建立／最後更新時間、狀態）→ Master 重開也知道收到哪裡。
- 排程：協定 1.2 的舊節點不支援傳回 → 勾了「傳回」的任務不派給它，排除原因「節點太舊，不能傳回」。
- `UPLOADING` 時節點離線**不判 UNKNOWN**（跟 RUNNING 不一樣），等到 D7 的 24 小時。

## 7. 畫面

- **📋 節點任務**：新增視窗多「下載完傳回這台」；列表狀態「傳回中 45%（12 MB/s）」「傳回中（Master 空間不夠）」；詳情顯示 Master 上的路徑、或「留在節點 xxx：路徑」＋「重新傳回」按鈕。
- **② 下載紀錄**：節點傳回的影片照樣出現，來源欄寫「節點 xxx」。
- **節點小視窗**：傳回進度；「傳完後節點這份：刪除／保留」。

## 10. 風險

- **大檔案經過標準庫 http.server**：一段 8 MB 用串流寫檔、不整段讀進記憶體以外的地方；PR2 先在 Windows CI 量 2 GB 檔的速度和記憶體，太慢再調段大小，並先跟你說。
- **同一台電腦測試**（127.0.0.1）測不出真實網路的斷線；AT-031 用程式模擬斷線，跨電腦要等有第二台電腦。
- 傳回會讓檔案在兩台各存一份一段時間：Master 驗證前節點不刪（D3），空間要算兩份。
