# S4 機器人跟產品分開 — 規格（2026-11-25 使用者選方案 B）

## 現況（2026-11-25 查）
- 最近一週 main 有 453 個 commit，其中 **372 個是機器人**（github-actions[bot]）寫狀態檔
- 會寫進 main 的 9 個 workflow：fx、fx-arena、weather、life、news、rank、dash、site-check、manual
  （寫的檔：`.github/*_state.json`、`news_seen.json`、`site_status.json`、`discord_manual_ids.json`、`docs/fx/rates.json`、`docs/fx/arena.json`）
- 這些 workflow 都有 `contents: write` → 它們的 token 理論上也能改程式碼（main 沒保護）
- 讀這些檔的：即時介面 `docs/dash`（RAW＝main）、換匯計算機 `docs/fx/calc.html`、Cloudflare Worker（RAW＝main）
- 機器人用到 14 個 Secret（Discord webhook 12 個、氣象署、環境部金鑰）；cron-job.org 約 8 個鬧鐘指向這個 repo

## 方案

| 我這邊的工作 | 大（搬 11 個 workflow、改所有路徑、轉址頁） | 中（9 個 workflow 改成寫 `bot-data`、3 個讀的地方改網址、一次搬資料） |

## 方案 B 的做法
1. 建 `bot-data` 分支（只有狀態檔，跟程式碼分開的歷史），把現在的狀態檔搬過去
2. 9 個 workflow：讀寫狀態檔都改在 `bot-data`（`git worktree`），推 `bot-data`，不再碰 main；main 上的狀態檔刪掉
3. 讀的地方改 RAW 網址到 `bot-data`：即時介面、換匯計算機（rates.json、arena.json）、Worker（你重貼一次）
4. 你在 GitHub 開 main 的規則：禁止強制推送、禁止刪除、只有管理員（你）能推 → 機器人的 token 推 main 會被拒
5. 測試：手動各跑一次（preview 模式）確認寫到 `bot-data`、main 沒有新 commit；即時介面、計算機、Discord 指令都正常

## 完成條件
- 一整天 main 上沒有機器人 commit
- 機器人推 main 會被擋（實測一次）
- 即時介面、計算機、Discord `/匯率` `/天氣` 等指令、鬧鐘、各頻道訊息都正常
