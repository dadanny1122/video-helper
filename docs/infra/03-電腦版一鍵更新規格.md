# 電腦版一鍵更新 — 規格（2026-11-26，待使用者確認）

## 目標
現在：電腦版發現新版 → 打開發布頁 → 自己下載 EXE → 自己換掉舊的。
之後：按「⬆ 更新到 vX.Y.Z」→ 程式自己下載、核對、換掉、重開；新版打不開就自動換回舊版。

## 流程
1. **發現新版**（跟現在一樣）：每次開啟問 GitHub `releases/latest`；新介面右上角／系統匣出現「⬆ 有新版 vX.Y.Z」，附更新內容
2. **按更新** → 下載 `VideoHelper.exe` 到 EXE 旁邊的 `VideoHelper.exe.new`（有進度條、可取消；下載中照常可用）
3. **核對（三關，全過才換）**
   - ① 大小、SHA-256 要等於發布頁上 GitHub 記的指紋（asset `digest`）
   - ② GitHub 要查得到本專案 `build.yml` 對這個指紋的打包簽章紀錄（attestation，跟現在「🔍 檢查這個 EXE」同一套）
   - ③ 發布頁的 `components.lock.json` 寫的 EXE 指紋也要一樣
   - 任何一關不過：刪掉下載的檔、顯示原因、不換
4. **換檔**：有下載中的任務 → 先問「要等下載完再更新嗎？」（預設等）；然後
   - 目前的 EXE 改名 `VideoHelper.exe.old`（Windows 允許改名正在執行的檔）→ `.new` 改名成 `VideoHelper.exe` → 開新版、舊版關掉
5. **新版自我檢查**：新版開起來 → 設定能讀、介面能開 → 寫「啟動成功」並刪掉 `.old`
   - 60 秒內沒寫「啟動成功」（打不開、閃退）→ 小幫手程序把 `.old` 換回來、重開舊版，並跳出「更新失敗，已換回 vX」
6. 設定、下載紀錄、配對、節點資料都在 `%APPDATA%`，不受換檔影響

## 不做／限制
- **不會自己偷偷更新**：一定要按（可在設定勾「有新版時自動下載好，等我按更新」）
- EXE 放在沒有寫入權限的資料夾（例如 `C:\Program Files`）→ 改成打開發布頁，請手動更新
- **節點（`--worker`）不自動換**：節點視窗只提醒；Master 換新版後，節點協定若太舊會照現在規則顯示「請更新節點」
- Nexus 資料庫不能降版：自動換回舊版時，如果新版已經升級過資料庫，節點功能要等你再更新一次才能用（會明講）
- 這不是完整的密碼學驗證（要 Sigstore 憑證鏈，得多裝套件、多連一個網站）；三關核對的前提是「GitHub 帳號沒被盜」，跟現在手動從發布頁下載的信任程度一樣，但多了指紋和簽章紀錄比對

## 會連到的網站（沒有新的）
`api.github.com`（版本、指紋、簽章紀錄）、`github.com`／`*.githubusercontent.com`（下載 EXE 和 lock 檔）——都已經在 SECURITY.md 和 `net_test.py` 的允許清單裡。

## 測試
- 單元測試：核對三關各種失敗（指紋不同、沒有簽章紀錄、lock 不一致、下載中斷）→ 都不換
- Windows CI（ci_smoke）：用「假發布」（本機假 GitHub 伺服器＋兩個版本的 EXE）實際走：下載 → 核對 → 換檔 → 新版啟動成功 → `.old` 被刪；再做一次「新版故意閃退」→ 自動換回舊版
- 你實機：等下一個版本出來時，按一次更新
