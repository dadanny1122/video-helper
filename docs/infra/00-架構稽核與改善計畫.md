# Repository 架構稽核與改善計畫（2026-11-25，基準 v1.45.0）

> 使用者 2026-11-25 要求做 Repository 架構稽核（只分析、不改檔）；報告確認後使用者說「是」＝從 S0 開始做。
> 完整報告在對話裡；這份是結論、依據和每個階段的狀態，給之後的人（和 AI）看。

## 結論

- **維持單一 Repository（方案 A）**，不拆 Desktop／Browser／Nexus。
  - 電腦版 import nexus 16 處（`video_helper_app.py` 27、744、2157、5245～6038、6840～6890 行）、Worker 用 `webui.i18n`（`nexus/worker/tray.py`）、`nexus/net/sites.json` 被電腦版、沙箱、`site_check.py` 共用
  - Nexus 跟電腦版是**同一個 EXE**，不可能單獨發布
  - 一個人開發，跨 repo 只會增加同步成本
- 真正的風險在：發布 tag 沒釘 commit、沒升版就不跑 Windows 測試、跟產品無關的機器人 workflow 有寫入權限（main 沒分支保護，抽樣 107 個 commit 裡 74 個是機器人）

## 階段與驗收

| 階段 | 內容 | 驗收 | 狀態 |
|---|---|---|---|
| S0 | 發布 `target_commitish: ${{ github.sha }}`＋發布後核對 tag；測試、打包、EXE 自我測試每次都跑，只有簽章／發布／通知看版號；workflow 最小權限（build.yml 頂層 read、只有 build job 寫；5 個只貼 Discord 的改 read）；全部 Actions 用 commit SHA 鎖（註解寫版本，Dependabot 每月更新）；build 加 concurrency | tag 的 SHA＝打包的 SHA（不一樣 workflow 失敗）；改程式不升版號也跑 Windows 測試 | ✅ 2026-11-25 |
| S1 | CI 產生 `components.lock.json`（desktop／browser／nexus／bridge_api／db_schema／sites.json／en.json／ffmpeg／mux.js／whisper 的版本和 SHA-256），附在 Release、一起簽章；SBOM 補非 Python 元件；說明書寫 Nexus 資料庫不能降版 | lock 檔每個指紋 CI 重算都一致；不含任何金鑰、憑證、使用者資料 | 待做 |
| S2 | 腳本每次 `@version` 改了打 `userscript-v3.x.y` tag＋附檔＋sha256；安裝來源要不要改指向 Release 由使用者決定（會影響 Greasy Fork 同步） | 任何一版腳本都能用 tag 找回、指紋跟 lock 檔一致 | 待做 |
| S3 | 相容性矩陣：新電腦版×上一版腳本、上一版電腦版×新腳本、新 Master×上一版 Worker | 三種組合每次發布前都過；LEGACY 表有測試 | 待做 |
| S4 | 機器人搬到另一個 repo（fx、fx-arena、weather、life、news、rank、dash、cloudflare、狀態檔、docs/fx、docs/dash）；主 repo 開分支保護 | 主 repo 沒有機器人 commit；機器人的 token 寫不進主 repo；鬧鐘、Discord、Pages 網址都正常 | 待使用者決定 |
| S5 | 新介面不依賴 `nexus.gui`、`MasterService` 由 App 直接建 | `_web_nexus_full` 不 import `nexus.gui`，測試照過 | 選做 |
